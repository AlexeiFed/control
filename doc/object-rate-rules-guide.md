# Как составлять правила ставок объекта

Краткое руководство для администратора и бухгалтера: как заполнять форму **«Правила ставок»** на карточке объекта, чтобы расчёт табеля и экспорты совпадали с ожиданиями.

## Зачем нужны правила

Одно правило задаёт **одновременно** две суммы в рублях (в интерфейсе — копейки считаются под капотом):

- **Клиент** — ставка для выставления счёта клиенту.
- **Сотрудник** — ставка для начисления охраннику.

**Единица** — «за час» или «за смену»: от неё зависит, как сумма умножается на сегменты времени при расчёте.

Правила хранятся **на объект**. Смена подбирает ставку по объекту смены, характеристикам охранника и календарю.

## Как система выбирает одно правило

1. Отбрасываются правила **другого объекта** и правила **вне периода действия** (`С даты` / `По дату`).
2. Из оставшихся берутся те, у которых **совпадают все заданные условия** (см. ниже про «Любой»).
3. Среди подходящих выбирается правило с **наибольшим приоритетом** (`priority`).
4. Если приоритет одинаковый — побеждает правило с **меньшим названием** по алфавиту (русская локаль), чтобы результат был предсказуемым.

**Важно:** приоритет — это не «порядок просмотра списка в UI», а число. **Чем выше число, тем раньше правило побеждает** при конкуренции. Имеет смысл давать узким правилам (ночь, праздник, стажёр) **больший** приоритет, чем «базовой» ставке.

## «Любой» / пустые фильтры = wildcard

Если поле условия в форме стоит **«Любой»** (или аналог **«Любая»**), оно **не сужает** правило: подойдёт любое значение этого признака.

Узкое правило — это когда вы явно задаёте:

- конкретный **день недели**;
- **праздник** да / нет;
- **тип смены** (обычная / усиление);
- **интервал времени** в течение локальных суток;
- **должность**, **удостоверение**, **трудоустройство**, **стажёр** — не «любой».

Чем больше заполненных фильтров при том же приоритете, тем **уже** правило и тем реже оно сработает; такие правила обычно ставят **выше по приоритету**, чем «базу».

## Поля формы по смыслу

| Поле | Смысл |
|------|--------|
| **Название** | Для человека и разрешения ничьей при равном приоритете. |
| **Приоритет** | Чем **больше**, тем сильнее правило среди подходящих. |
| **Единица** | За час — почасовой тариф; за смену — ставка на целый сегмент с подходящей единицей в расчёте. |
| **Клиент / Сотрудник** | Суммы в рублях для сторон. |
| **С даты / По дату** | Локальная дата смены в часовом поясе расчёта должна попадать в интервал. Пустое «По дату» — бессрочно после «С даты». |
| **День недели** | Понедельник = 1 … воскресенье = 7. «Любой» — без фильтра по дню. |
| **Праздник по календарю** | Сверка с календарём праздников в системе на **локальную дату** смены. «Да» — только праздничные дни; «Нет» — только непраздничные; «Любой» — без фильтра. |
| **Тип смены** | Обычная / усиление (`Regular` / `Reinforcement`) или любой. |
| **Интервал с / по** | Окно **локального** времени суток для **минутного** разбиения смены. Пусто в обоих — без ограничения по часу. Интервал **полуоткрытый** `[начало, конец)` — граница «по» не входит. Если «с» позже «по» (например 20:00–08:00), окно считается **через полночь**. |
| **Должность** | Старший поста / охранник или любая. |
| **Удостоверение** | Если в правиле указан тип удостоверения, **старший смены** (`ShiftLead`) **никогда** не матчится этим правилом (у него нет лицензии охранника в модели). |
| **Трудоустройство** | Штат / не оформлен и т.д., или любое. |
| **Стажёр** | Да — только стажёры; Нет — только не стажёры; Любой — без фильтра. |

## Практические рекомендации

1. **Базовая ставка** — одно широкое правило: высокий приоритет не обязателен, но удобно дать название вроде `00 база` и приоритет **ниже**, чем у исключений.
2. **Ночь / выходные / праздник** — отдельные правила с **большим** приоритетом и заполненными днём / праздником / интервалом.
3. **Усиление** — отдельное правило с типом смены «усиление» и приоритетом не ниже базы.
4. **Стажёр** — отдельное правило «Стажёр = да» и ставками ниже; приоритет обычно **выше** базы, чтобы перекрывать общее правило.
5. **Пересечение периодов** разных правил с одним приоритетом — избегайте: при равном приоритете победит **имя** правила, что может быть неочевидно. Лучше развести **даты** (`По дату` / новое правило со следующего дня) или **приоритеты**.

## Связь с часовым поясом и календарём

День недели, «полночь» и интервалы считаются в **часовом поясе**, заданном для расчёта смен (в коде табеля/калькулятора). Праздники сопоставляются по **локальной дате** в этом же поясе.

## Если подходящего правила нет

В табеле смена может помечаться как **без ставки** (`unpriced`): нужно добавить правило или смягчить условия (чаще всего — забытый праздник, ночное окно или тип смены).
